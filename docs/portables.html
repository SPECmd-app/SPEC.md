Judo Club Website

The canonical SPEC.md example, and also a fully implementable portable. It specifies a small multilingual club website: its pages, language behavior, schedule, gallery, contact handoff, logical model, constraints and verification. The same file can be built with very different technologies while preserving the same required behavior, which makes it a good first spec to read and a good one to hand to a coding agent.

This website

The specification of this very site, with a paired TRACE.md that maps each requirement to the files and checks that satisfy it. It covers the version links the homepage must show, the machine-readable discovery files (llms.txt, robots.txt, structured data), the companion-tooling section, a rule that the site has no outside dependency, and consent-gated analytics. A good example of a spec describing something you can open in a browser and check.

specmd CLI

The specification and paired TRACE.md for the companion command-line tool and MCP server, and a Core plus Optional example that uses trace pairs, an interface contract and normative modules. It shows how a spec can describe what a tool promises, and what it deliberately does not yet do. This is a snapshot copy; the modules it declares live only in the specmd-cli repository, so their links won't resolve here.

Internal IT ticketing

A deliberately small, Core-only spec for an internal IT service desk: employees report issues, and IT agents work them through Google or Microsoft sign-in. Only four decisions have been made (the type of service desk, sign-in for agents, a single organization, and the intake channels: web portal, API and email). Everything else is left as TBD or an open issue rather than guessed, which shows how a spec grows section by section as decisions are made.

Headless BPM

The specification for a durable, BPMN 2.0-aligned business-process orchestration system with no built-in interface: it is operated entirely through a CLI, REST APIs and MCP, so people, services, workers and AI agents can take part in the same process. It is the most extensive portable here, covering process authoring and interchange, runtime state, entry points, actors and tasks, incidents, recovery, and fleet-scale operations. It uses the Optional standard's requirement metadata, Mermaid diagrams, composed verification and a paired TRACE.md, plus a logical ERD companion. A reference implementation now exists, and the trace's evidence comes from its own test runs.

Karesansui zen garden

The specification and paired TRACE.md for 枯山水 Karesansui, a single-file browser game: rake the sand, set stones and plants, and tend the garden through the seasons. It specifies the experience as well as the rules: exact simulation tables and a Tranquility score, a garden file format, how the game is laid out on the web and on a phone, and every message, timing and small-screen rule, so that another builder produces a game that plays and reads the same.
